# astock-workbench

一个面向沪深 A 股的终端工作台：用小体积 Go 二进制实时看盘，用独立 Python 适配器调用
TradingAgents-Astock 做多智能体策略研究，并为模拟盘、回测和量化执行预留严格隔离的接口。

## 当前能力

| 能力 | 状态 | 说明 |
|---|---|---|
| 实时行情 | 可用 | CLI 默认通达信 TCP，报价/日 K/分时异常时分别自动回退 HTTP |
| 本地 Web 行情图 | 可用 | Vue + Go 行情 API，含分时/日 K、成交量、MA5/20/60、涨跌停边界和自动刷新 |
| 股票、转债、板块名称/代码 | 可用 | 支持沪深股票、110/113/118/123/127/128 转债和 BK 板块代码/名称 |
| 自选资产 | 可用 | CLI 与 Web 共用分组、顺序和自选文件，Web 支持切换、添加和移除股票、转债、板块 |
| 摸鱼/拼音模式 | 可用 | 无颜色带框表格，股票、自选板块和外盘指数均支持无声调拼音 |
| 五档盘口 | 可用 | 标准视图下显示买卖五档 |
| 市场榜单 | 可用 | 涨幅、跌幅、快速涨幅前 20，包含行业板块 |
| 主力资金雷达 | 可用 | 当前自选组/榜单的 1/3/5 分钟资金变化、行业共振与行为标签 |
| 板块资金看板 | 可用 | `y` 查看行业主力流入/流出 Top 5 及每板块成交额前三核心股 |
| 智能市场报告 | 可用 | 后台扫描大盘量能、板块承接、热门龙头与 A/B/C 智能观察池，附冻结信息凭证 |
| 个股多维研判 | 可用 | 技术、资金、热门板块、龙虎榜、公告、新闻与券商观点的可追溯 AI 报告 |
| 看盘 AI 咨询 | 可用 | `x` 后台咨询当前股票，自动带入实时多维数据并持久化该股历史问答 |
| 日线交易信号 | 可用 | 看涨/看跌/震荡、条件买卖点、失效位与仓位策略 |
| 多智能体分析 | 可用 | 适配本地 TradingAgents-Astock，不复制其源码 |
| 分析归档 | 可用 | 每次保存完整 JSON 和 Markdown |
| 模拟盘 | 接口已预留 | 撮合、持仓流水尚未实现 |
| 回测 | 可用（第一阶段） | 日线放量突破/趋势策略、A股撮合、逐笔交易审计与资金曲线 |
| 多Agent持续优化 | 可用（研究） | 子Agent提案、滚动验证、最终留出、压力测试和模拟观察门禁 |
| 实盘交易 | 仅接口边界 | 默认不存在实盘 Broker，研究信号不能直接下单 |

## 快速开始

要求 Go 1.24 或更高版本：

```bash
cd /Users/wenzhe/astock-workbench
make test
make build
./dist/astock watch --once 600519
```

持续看盘：

```bash
./dist/astock watch 贵州茅台 平安银行
./dist/astock watch --moyu 贵州茅台 平安银行
./dist/astock watch --pinyin 600519 000001
./dist/astock watch --depth 贵州茅台
./dist/astock watch --interval 5 贵州茅台   # 改为每 5 秒刷新
```

本地 Web 行情页：

```bash
./dist/astock web --listen 127.0.0.1:8765
```

CLI 默认使用通达信 TCP 行情源，底层为 MIT 许可的 `tdxrs`（Python 3.11+）：

```bash
make tdx-setup
./dist/astock watch --source tdx --once 002080
./dist/astock web --source tdx --listen 127.0.0.1:8765
```

CLI 无需传 `--source` 即会选择 TDX；需要临时切回原行情源时使用
`./dist/astock watch --source http`。Web 仍默认 HTTP，显式传入 `--source tdx` 后才切换。

也可用 `ASTOCK_TDX_PYTHON` 指定已安装 `tdxrs` 的 Python，使用
`ASTOCK_TDX_SERVER=host:port` 固定节点。TDX 模式复用持久 TCP 连接获取实时快照、未复权日 K
和当日分时；名称、涨跌停、换手率等元数据按 30 分钟缓存从腾讯补齐。报价、日 K、分时分别
检测和回退，单项 TCP 连接或解析失败时只将该项切回现有 HTTP 源。资金、板块、榜单、公告和
新闻继续使用原有数据源。

通达信 TCP 是持久连接上的请求/响应协议，不是 WebSocket，也不是服务器主动推送。它能避免
每次刷新都建立 HTTP 请求，但程序仍会按 CLI/Web 的刷新间隔主动查询；公共节点不承诺 SLA，
生产使用应保留当前自动回退和合理的请求间隔。

浏览器打开 `http://127.0.0.1:8765/`，默认显示共享自选列表的第一只股票；也可通过位置参数或 `--symbol`
指定首次打开的股票。页面顶部显示上证、深证、创业板指数的最新价和涨跌，以及今日成交额总计、
较上一交易日增减额和增减幅；点击指数即可切换到对应的
分时与未复权日 K；页面支持分时、未复权日 K 和共享自选，行情接口与 CLI 共用已选择的数据源、HTTP 回退
和本地缓存，每 10 秒刷新一次。图表只读，价格、均线、成交量和涨跌停线用于观察，
不构成交易指令。

Web 搜索框和自选添加框同时支持股票、可转债和板块：例如 `113001`、`123001`、`BK0438`
或 `食品饮料`。股票和转债显示分时/日 K；板块显示涨跌、主力净流入、上涨/下跌家数和成交额前五
龙头。CLI 的 `astock add` / `astock list` 也共用这些资产代码；仅查询板块时会输出板块资金快照，
混合自选中的板块由 Web 板块视图查看。
正常 `make build` 直接使用仓库内已经构建并嵌入的 Web 资源；修改 `web/` 下的 Vue 源码后先执行
`cd web && npm install`，再执行 `make web-build` 更新 `internal/web/dist/`。

从 9:15 集合竞价开始默认每 1 秒刷新，可通过 `-i` 或 `--interval` 配置为 1–3600 秒。
9:15-9:25 显示“集合竞价”，9:25-9:30 显示“开盘等待”；午休、收盘后和周末保持界面
可操作，但不再持续请求行情，进入下一个可轮询时段后自动恢复。程序启动时始终获取一次
快照，标题会显示市场状态和最近一次成功刷新的时间点。

持续模式使用终端备用屏幕原位重绘，不增加主终端滚动记录；按 `Ctrl-C` 退出后会恢复
运行前的 shell 画面。使用 `↑/↓` 或 `j/k` 选择个股，按 `Enter` 打开完整详情，按 `Esc`
返回列表；`[/]`、`PgUp/PgDn` 或 `b/空格` 用于跳选或详情翻页，`g/G` 选择首尾，`q` 退出。
在持续模式底部会显示当前可用操作；按 `a` 后输入代码或名称添加自选，按 `d` 删除箭头当前选中的自选并进行二次确认，
按 `i` 后输入代码或名称可直接查看该股票详情；按 `h` 打开最近查看历史并选择恢复，最新查看的
股票排在最前面，再次查看已有股票会将它移到第一位。默认/全部分组中按 `m` 可为箭头当前股票分配分组，
用 `↑/↓` 移动、`空格` 多选或取消，`Enter` 保存；每个分组会标记当前已加入、将加入或将移出状态。
名称匹配到多只股票时，可用 `↑/↓` 选择候选并按 `Enter` 确认。
命令输入支持退格，`Esc` 取消。
在列表、详情、榜单、资金雷达、板块资金、AI 问答和报告页按 `t`，统一进入“策略研究中心”。
页面内可以选择当前股票或进入页面前的当前列表（自选组、榜单或资金雷达股票池），直接运行单次回测
或训练/验证/样本外优化；设置页可切换回测年限、日期划分、候选数量、验证最低交易数和 Codex
只读复盘。耗时任务启动后自动回到看盘，底部持续显示候选进度，行情和资金采样不停止；完成后再按
`t` 直接进入结果。页面内还可查看所有回测/优化历史、候选排名、样本外逐笔交易，并从回测交易行
继续查看买卖信号、次日开盘成交、费用、持有天数、最大浮盈/浮亏和退出原因。外部 `backtest`
子命令仍保留给脚本和批处理使用，日常看盘不需要离开看板。
基础操作栏分两行显示：第二行按 `1` 打开涨幅榜前 20，按 `2` 打开跌幅榜前 20，按 `3`
打开快速涨幅榜前 20。榜单包含代码、名称、涨跌幅、涨速和行业板块；方向键选择，`Enter`
进入详情，`Esc` 返回榜单或自选列表。再次按当前数字键会获取最新榜单。
交易时段内榜单会随行情刷新间隔自动更新，默认每秒更新一次；午休、收盘后和周末保留最近一次榜单。
进入看盘后，当前自选池会在后台自动预热东方财富个股累计主力净额和行业资金快照，不切换页面；
交易时段内个股每 10 秒采集一次，内存保留最近 6 分钟样本，行业资金每 60 秒刷新。之后在自选列表
或任一榜单按 `v` 打开主力资金雷达，已有样本会直接用于计算 1/3/5 分钟净额变化，不必从零等待。
雷达默认按 1 分钟主力资金变化降序排列；尚未积累完整 1 分钟样本的股票排在已采样股票之后。
宽屏下行业名称和板块净流入/净流出金额分列显示；行业资金暂缺时保留行业名称，并在板块资金列显示 `--`。
价格仍按行情刷新间隔更新，用于显示个股与行业同向流入/流出、资金反转、加速和价资背离等行为标签。
雷达内用方向键选择、`Enter` 查看详情、`Esc` 原路返回，按 `v` 可立即刷新；非交易时段不会自动轮询，
但仍允许手动刷新。行为标签是短线观察证据，不是确定性的买入或卖出指令。
在自选列表、榜单、详情或资金雷达按 `y`，可在同一看板查看行业板块主力净流入 Top 5 和净流出
Top 5；每个板块同时列出板块内成交额最高的 3 只高流动性核心股，以及个股涨跌、涨速和累计主力
净额。这里的“龙头”是明确的成交额排名口径，不代表官方认定或基本面行业地位。看板后台加载时行情
继续刷新；交易时段仅在看板可见时每 60 秒最多自动更新一次，按 `y` 可手动刷新。主节点正常返回时
每轮包含 2 个板块排名请求和最多 10 个成份股请求，成份股查询最多 4 路并发；接口失败时会尝试现有
公开备用节点。单个板块失败不会清空其他板块，
整轮失败则保留上一次成功结果。用方向键滚动、`[/]` 翻页、`g/G` 到首尾，`Esc` 返回。
在任意看盘页面按 `s` 会启动后台市场扫描，行情、榜单和资金雷达继续正常刷新；状态栏显示当前
采集/计算/Codex 综合阶段。完成后状态栏提示按 `r` 打开报告，报告页用方向键滚动、`[/]` 翻页，
`h` 打开按日期、日期内按生成时间归档的市场报告历史，`Esc` 返回原看盘页面。`r` 始终直接打开
最新一份报告。扫描综合三大指数未复权日线和量能、沪深京成交额、行业涨跌/主力资金/广度、
全市场成交额与主力榜、候选股 5/20/60 日结构及近期公告索引；观察池分为 A 板块龙头/核心承接、
B 高波动情绪候选和 C 超跌反转观察，热门板块龙头保留独立席位，同一行业最多两只。

也可直接运行 `./dist/astock scan`；`--no-ai` 只生成确定性量价版，`--full` 同时打印全文。
默认 Codex 以临时会话、只读沙箱和无需确认模式接收结构化行情 JSON，不读取仓库、不搜索网络、
不修改文件且不触发交易；调用失败或超时会自动保存量化回退报告。报告归档在
`~/.local/share/astock-workbench/market-reports/<时间戳>/`，包含 Markdown、快照 JSON、Agent 结果、
独立的 `evidence.json` 信息凭证和元数据。市场扫描只为最终观察池前 5 只候选采集近 90 日券商
研报，并采集近 7 日市场新闻线索，避免对全市场逐股发起额外请求。
可用 `ASTOCK_CODEX_BIN`、`ASTOCK_CODEX_MODEL`、`ASTOCK_CODEX_PROFILE` 和
`ASTOCK_CODEX_TIMEOUT_SECONDS` 覆盖 Codex 可执行文件、模型、配置档与 30-1800 秒超时，默认 600 秒。
在自选、榜单、详情或资金雷达中按 `c`，会在后台生成当前股票的多维研判，行情继续刷新；完成后
按 `o` 打开最新一份；报告详情中按 `h` 可按日期、日期内按生成时间查看该股票的其他历史研判。
报告分别给出短线/波段多空理由、当前累计主力与可用的1/3/5分钟变化、关联板块涨跌/
主力/广度/排名、近30日龙虎榜、公告和第三方新闻标题线索，以及来自未复权日K的支撑、压力、
买入观察条件、卖出/减仓观察条件和判断失效位。点位必须沿用MA20/MA60或20日结构高低点，
Codex不得创造数据中没有的价格；报价中的当日涨停/跌停价是硬边界，超出边界的技术位只能标成
跨交易日结构位，不能写成今日收盘、盘中买卖或止盈止损条件。新闻和公告标题不能当成已经核验的公司事实。
外部信息按 A/B/C/D 四层标记：已读取并核验的交易所、巨潮或公司正式披露正文为 A 层；东方财富公告
索引目前只算 C 层待核线索；券商研报为 B 层专业观点；财经新闻为 C 层背景线索；经白名单接入的市场
评论只能归入 D 层情绪。B/C/D 均不能单独支撑买卖结论。

在自选、榜单、详情或资金雷达中按 `x` 输入问题，例如“现在是否适合买入”“我的成本是 25 元、
三成仓位应该怎么观察”。提交后立即回到行情刷新，状态栏显示 Agent 的数据采集和回答进度；完成后
再按 `x` 打开可滚动回答页，回答页按 `x` 可继续追问同一只股票。切换股票后按 `x` 会恢复该股历史；
最近 100 轮按股票保存在 `~/.local/share/astock-workbench/ai-chats/<代码>/conversation.json`，重启后仍可查看，
送给 Agent 的上下文只取最近 6 轮以控制长度。每次问答自动带入当前行情、未复权日 K 技术结构、当日累计资金、
可用的 1/3/5 分钟资金、行业/关联板块资金与广度、龙虎榜、公告索引和新闻线索。Agent 必须给出
条件式买卖/持有判断及依据、触发、失效和风险；缺失持仓成本、仓位或周期时不会自行假设。Codex
继续以临时会话、只读沙箱、无需确认模式运行，不读取文件、不搜索网络、不调用交易接口；行情、
榜单和资金采样在后台继续，回答不会触发自动交易。

市场报告、个股研判、AI 咨询和策略研究可以同时在后台运行，只阻止同一类任务被重复启动。`x/c/s` 使用共享事实快照的多角色 Agent 工作流：角色只读分析冻结数据，主 Agent 负责证据冲突、时效和价格边界校验；任何角色失败都会显示并降级为确定性报告，不会阻塞行情。看盘
状态区会为每个运行中、已完成或失败的任务保留独立一行；其中一个任务失败不会覆盖其他任务进度。

CLI 使用 `./dist/astock stock-report 600519`，`--no-ai` 生成确定性版，`--full` 打印全文。
报告保存在 `~/.local/share/astock-workbench/stock-reports/<代码>/<时间戳>/`，包含 `report.md`、
`snapshot.json`、`agents.json`、`evidence.json` 和 `metadata.json`。个股报告采集近 30 日公告索引、
近 7 日新闻和近 90 日最多 5 篇券商研报，报告末尾展示 `[E##]`、来源、作者、日期和原文入口。
可用 `ASTOCK_STOCK_NEWS_API_URL` 与 `ASTOCK_BROKER_RESEARCH_API_URL` 指定兼容代理；正式结论
仍以交易所、巨潮或公司公告 PDF 正文为准。
个股和市场研判成功获取的未复权日K会缓存在 `~/.cache/astock/daily-history/`；在线接口临时返回
空数据、HTTP 501或超时时，允许回退到14天内的最近有效缓存，并在数据源中标记“缓存”。龙虎榜、
新闻、公告或板块等可选维度失败只降低报告完整度，不会被误写成日K失败原因。
非连续交易时段或东方财富主力字段暂不可用时，市场扫描会生成低置信度观察池，明确提示开盘后复核；
连续交易时段且资金数据可用时，仍执行上涨、净流入和量价结构的严格筛选。
输入状态和快捷键操作栏分开显示，输入位置带闪烁光标；操作完成或失败后的状态提示保留 5 秒后自动清除。
股票较多时列表会围绕当前选择自动取可见窗口。`--once` 仍以普通文本输出完整单次快照。

## 日线策略回测

持续看盘时优先按 `t` 使用统一策略研究页面。以下命令适用于自动化脚本或需要精确传入全部参数的场景。

第一阶段回测引擎使用固定的不复权日 K，默认运行“放量突破 + MA20/MA60 趋势”策略。信号在当日
收盘后生成，实际买卖安排在下一可成交交易日开盘，模拟 A 股 T+1、100 股整手、佣金、最低佣金、
卖出印花税、过户费和双向滑点。止损、止盈、跌破快线和最大持有期均为可配置的确定性规则。
长历史默认用腾讯明确的 `none` 不复权序列单次请求，失败后回退东方财富；实际来源会写入结果。

运行回测：

```bash
astock backtest run \
  --start 2022-01-01 \
  --end 2025-12-31 \
  --cash 1000000 \
  --max-position 0.20 \
  --slippage-bps 5 \
  600519 000001 300750
```

查看历史、汇总和交易买卖点：

```bash
astock backtest list
astock backtest show <run-id>
astock backtest trades <run-id>
astock backtest trade <run-id> T0001
```

单笔交易会分别列出信号日期和实际成交日期、信号时的均线/前高/量比、买卖理由、原始开盘价、
滑点后成交价、股数、费用、持有天数、净收益、最大浮盈、最大浮亏和退出原因。每次结果保存在：

```text
~/.local/share/astock-workbench/backtests/<run-id>/
├── summary.json       # 完整回测结果、指标、交易和未平仓
├── strategy.json      # 策略参数与交易成本快照
├── report.md          # 可读报告和交易摘要
├── trades.jsonl       # 逐笔交易审计记录
└── equity.csv         # 每日现金、持仓市值、权益和回撤
```

当前限制会写入每次报告：不复权序列跨除权除息可能失真；静态输入股票池不等于历史点时成份股池；
日 K 只能识别一字板，不能重建盘中涨跌停排队和真实成交概率；交易费率按本次参数固定，不会伪装成
按历史政策日期自动切换。回测归档将作为后续训练/验证/样本外
划分和 AI 参数建议的输入，但 AI 不会直接修改成交记录或绕过撮合规则。默认期末强平按最后可成交日
收盘价做估值收尾并计入卖出成本，报告会明确它不是次日开盘的真实成交。

### 训练、验证与样本外优化

策略优化使用受控的确定性参数候选，默认最多 30 个。候选只根据训练集和验证集评分，并经过验证
交易数、最大回撤、最低收益、训练/验证年化差距和有限数值门禁。参数锁定后才执行一次样本外回测；
样本外结果不会用于重新挑选参数。每个区间从相同初始资金独立开始，不跨区间携带持仓，预热日 K
只取该区间开始日之前的数据。候选复用进程内历史区间缓存，不会按候选数重复请求相同行情。

```bash
astock backtest optimize \
  --train-start 2018-01-01 --train-end 2021-12-31 \
  --validate-start 2022-01-01 --validate-end 2023-12-31 \
  --oos-start 2024-01-01 --oos-end 2025-12-31 \
  --max-candidates 30 \
  600519 000001 300750

astock backtest optimize-list
astock backtest optimize-show <experiment-id>
```

默认在确定性实验结束后调用临时、只读、非交互的 Codex 复盘训练/验证泛化差距、参数敏感性和
失效场景；用 `--no-ai` 可关闭。AI 只能输出复盘文本，不能生成成交、改写指标、绕过验证门禁或
按样本外结果重选参数。AI 失败也会保留完整实验。实验单独保存在：

```text
~/.local/share/astock-workbench/backtests/optimizations/<experiment-id>/
├── summary.json
├── candidates.jsonl
├── selected-strategy.json
├── report.md
├── ai-review.md                 # AI 成功时存在
├── train/                       # 入选候选的完整回测归档
├── validation/
└── out-of-sample/
```

参数搜索和样本外盈利都不等于“稳定收益”。当前仍使用静态输入股票池、固定历史费率和不复权日 K；
正式研究还应增加历史点时股票池、公司行动处理、滚动走样本检验及不同市场状态压力测试。

### 多Agent持续优化

持续模式使用 Go 主协调器并发启动三个只读子 Agent，分别从稳健风控、趋势捕获和参数平台稳定性
提出结构化候选。子 Agent 只能修改受控技术参数，不能看到最终留出结果，不能修改股票池、仓位上限、
费用、滑点、复权、评分或晋级门槛；任一 Agent 超时或格式错误时，确定性基线候选仍会继续研究。

```bash
astock backtest continuous 600519 000001 300750
astock backtest continuous-list
astock backtest continuous-show <experiment-id>
```

当前策略族支持放量突破、重新站回快均线、均线回踩收回三种入场模式。候选默认经过4折滚动训练/验证；
参数锁定后才运行最近3个月的最终留出集，并用双倍交易成本与最佳单笔利润集中度做压力测试。只有滚动
正收益窗口、交易数、最终留出收益/夏普/回撤和压力测试同时通过，才标为“模拟观察候选”；否则保留为
“研究候选”。模拟观察候选也不会自动替换看盘信号或下单，仍需后续真实时间的影子运行和人工确认。

每轮还会生成候选集和完整配置的 SHA-256 指纹，执行无未来数据、滚动窗口、复权口径和行情来源完整性
硬检查，并记录点时股票池和基准的已知限制。多个 Agent 独立提出相同参数会形成共识证据；入选参数
附近没有同样通过门禁的参数邻域时，即使单点评分最高也不会晋级。`continuous-show` 和 `t` 页面会展示
质量评级、指纹、共识、参数邻域、历史反思和全部未晋级原因。

同一股票池的最终留出区间不能重叠，避免在已经查看过的测试集上继续调参。默认至少积累一个新的完整
3个月留出窗口后，系统才会将上一轮锁定参数和已完成反思作为新一轮基线，再重新执行全部滚动、留出
与压力测试。

完整设计、开源项目借鉴和后续数据治理优先级见
[docs/STRATEGY_RESEARCH.md](docs/STRATEGY_RESEARCH.md)。
在持续看盘的 `t` 策略研究中心可直接启动任务，并查看独立的持续优化历史、子 Agent 状态、未晋级
原因和主 Agent 监督复盘。实验归档位于：

```text
~/.local/share/astock-workbench/backtests/continuous/<实验ID>/
```

普通模式的列表用于快速选择，并显示个股主力资金净额、涨停和跌停；上涨/流入用 `↑`，下跌/流出用 `↓`，
“涨跌”后显示东方财富 `f22` 实时涨速，字段暂不可用时显示 `--`；
标准模式保留红涨绿跌颜色。进入详情后包含当前价、涨跌、
昨收/今开、买一/卖一及挂单量、日内价格区间，以及成交量、成交额、换手、振幅、量比、均价、
PE(TTM)、PB、总/流通市值、涨跌停价和主力资金净额/净占比。`--depth` 会在详情中展开完整五档。
详情还会显示关联度最高的 6 个行业/概念板块，包括板块涨跌、主力净流入/净占比和领涨股，
并判断关联板块是多数流入、多数流出还是资金分化，以及个股资金方向是否与板块一致。
关联板块来自东方财富 F10 的行业与精确概念排名；地域、指数、风格和持仓标签不纳入这 6 项。
每个板块还会给出同类板块的涨幅/主力资金/换手 Top 100 排名、上涨/下跌家数，并标记热门、热门分歧、活跃、一般或偏冷。
若个股近 30 日登上龙虎榜，详情会列出最近 3 条上榜记录的触发原因、买卖额、净买入、榜单成交占比、换手、席位标签和可用的上榜后表现；这些是短线行为证据，不替代公告、财报或买卖决策。

进入个股详情后还会异步加载约 300 根未复权日 K，给出日线波段的“看涨 / 看跌 / 震荡”方向，
以及“买入触发 / 买入观察 / 持有观察 / 减仓观察 / 卖出触发”。计算依据包括 MA5/20/60、
MACD、RSI14、前 20 日结构高低点和相对 20 日均量；每个结论同时展示买入条件、卖出条件、
失效条件、支撑/压力来源和分批仓位方案。`CALL-like` / `PUT-like` 只是与外盘软件相似的
方向标签；`PUT-like` 在普通 A 股账户中表示看跌、减仓或离场观察，不代表个股可以直接做空。
主力资金、板块热度和龙虎榜会作为独立短线侧证展示，但不参与基础量价信号打分。

日 K 默认先请求东方财富，数据为空或接口失败时自动回退到腾讯明确指定的未复权 `day` 序列；
详情会显示本次实际数据源和数据日期。交易时段内同一股票最多每 5 分钟刷新一次技术信号，
午休、收盘后和周末不会持续请求。可通过 `ASTOCK_DAILY_HISTORY_API_URL` 和
`ASTOCK_DAILY_HISTORY_TENCENT_API_URL` 指定兼容代理，分别支持 `{secid}` 和 `{symbol}` 占位符。
`--moyu` 使用无色紧凑表格，同样显示个股资金流，并在列表顶部显示上证、深证、创业板的指数资金；
`↑` 表示净流入，`↓` 表示净流出；普通列表和详情的个股/关联板块资金流最多每 60 秒更新一次，
资金雷达仍按前述 10 秒/60 秒节拍独立采样。顶部以“沪深成交额”显示
沪深京 A 股合计；创业板是深市子集，不会重复累加。当前值使用腾讯的上证指数、深证综指和北证 50
成交额字段，上一交易日使用新浪对应指数的 5 分钟成交额逐日精确汇总，不使用成交量估算，也不需要
Token。该口径实测与常见行情软件的“沪深京”总额和缩放量差值一致。

历史数据暂不可用时只显示当前总额，不显示“较昨”；周末、节假日和开盘前若行情日期尚未推进到
新交易日，也会隐藏对比，避免同一天金额相减。可通过 `ASTOCK_SINA_AMOUNT_HISTORY_API_URL`
指定兼容代理，并使用 `{symbol}` 作为指数代码占位符。

板块排行和龙虎榜数据使用东方财富公开接口。可通过 `ASTOCK_BOARD_RANK_API_URL`、
`ASTOCK_DRAGON_TIGER_API_URL` 指定兼容的代理地址；板块排行按行业/概念缓存 5 分钟，龙虎榜按股票缓存 30 分钟。
个股涨跌幅榜和涨速榜同样使用东方财富沪深 A 股列表接口，行业板块取其 `f100` 分类；可通过
`ASTOCK_MARKET_RANK_API_URL` 指定兼容代理，也可使用 `{metric}`、`{order}`、`{limit}` 占位符。
资金雷达的全行业资金快照使用东方财富行业板块列表接口，可通过 `ASTOCK_INDUSTRY_FLOW_API_URL`
指定兼容代理地址。
板块资金看板使用同一行业板块列表口径按主力净额双向排序，再用板块成份股列表按成交额取前三；
可通过 `ASTOCK_INDUSTRY_SCAN_API_URL` 和 `ASTOCK_INDUSTRY_LEADER_API_URL` 分别指定兼容代理地址。

自选股：

```bash
./dist/astock add 贵州茅台 宁德时代
./dist/astock remove 宁德时代
./dist/astock list
./dist/astock                 # 读取已保存自选并持续刷新
```

持续看板支持有序分组。按 `f` 打开分组列表，方向键选择、`Enter` 切换；列表内按 `n` 新建分组、
按 `d` 删除分组。看某个具体分组时，`a` 添加到该组，`d` 只从该组移出；在“全部”视图按 `d`
才会从所有分组删除。删除分组不会丢失独有股票，它们会自动移到“默认”。

按 `e` 进入排序模式：先用方向键选择股票，第一次 `Enter` 锁定，继续用方向键移动，第二次
`Enter` 保存；任一阶段按 `Esc` 都会恢复进入排序前的顺序。“全部”是多个分组的汇总视图，
需要先按 `f` 进入具体分组再排序；只有“默认”一个分组时，启动后可直接按 `e`。

分组仍保存在兼容的 `~/.config/astock/watchlist` 文本文件中，使用 `[分组名]` 标题；旧版单列表
会自动作为“默认”分组读取。`astock list` 会按分组罗列自选。

通过 `i` 或 `h` 成功打开的最近 100 只股票保存在
`~/.local/share/astock-workbench/view-history.tsv`，普通列表中按 `Enter` 查看不会写入这份历史。

兼容原来的简写：`astock 600519`、`astock --moyu 600519`、`astock --add 600519`。

## 接入 TradingAgents-Astock

`watch` 完全不需要 Python。只有 `analyze` 需要：

1. 一个可工作的 `tradingagents-astock` checkout；
2. 该项目的 Python 3.10+ 虚拟环境；
3. 对应模型供应商的 API 凭证。

本机已有项目时，先自检：

```bash
./dist/astock doctor --repo /Users/wenzhe/tradingagents-astock
```

运行一次分析：

```bash
./dist/astock analyze --repo /Users/wenzhe/tradingagents-astock 600519
```

也可以固定环境，之后不再传路径：

```bash
export ASTOCK_TRADINGAGENTS_HOME=/Users/wenzhe/tradingagents-astock
export ASTOCK_TRADINGAGENTS_PYTHON=/Users/wenzhe/tradingagents-astock/.venv/bin/python
./dist/astock analyze 贵州茅台
```

覆盖模型配置的例子：

```bash
./dist/astock analyze \
  --provider deepseek \
  --deep-model deepseek-chat \
  --quick-model deepseek-chat \
  600519
```

未显式传入时，provider、模型和 backend URL 均沿用 TradingAgents-Astock 的
`DEFAULT_CONFIG` 与环境变量。模型密钥不会复制进本项目，桥接进程只继承当前环境并读取
TradingAgents 项目自己的 `.env`。

一次完整分析通常会产生 30–50 次模型调用，可能耗时数分钟并产生 API 费用。`doctor`
只验证本地环境，不发起正式分析。

结果默认保存到：

```text

├── analysis.json
└── report.md
```

查看历史：

```bash

```

稳定 JSON 契约包含：标的、分析日期、五档组合评级、provider/model、数据供应商、全部

不直接导入 LangGraph。

## 数据和风险边界

- 实时表格是公开 Level-1 快照，不等同于交易所直连行情，也不保证逐笔或毫秒级实时性。
- 个股和指数资金流来自东方财富公开口径，是市场行为参考；主接口不可用时会回退到公开延迟节点。
- 指数资金分别对应三大指数的主力净额，指数成分股存在重叠，不能把三项相加当作全市场总额。
- 技术判断使用未复权历史日 K 和量能；实时快照只用于展示与分析时点提示。日线信号不等同于盘中高频点位。
- 财务、公告、减持、合同等正式结论应回到交易所或巨潮资讯原文核验。
- 报告和详情页输出是情景研究信号，不是确定性买卖建议；应明确触发条件、仓位和失效条件。
- 研究、回测、模拟撮合和未来实盘 Broker 是不同进程/接口，实盘层必须再经过确定性风控与人工确认。
- 回测实现时必须固定复权口径，并处理未来函数、幸存者偏差、点时股票池、手续费和滑点。

## 路线图

1. 回测历史 K 线持久化缓存和复权口径扩展；
2. 确定性技术信号与 TradingAgents 研究信号合成；
3. AI 参数候选、训练/验证/样本外和滚动回测；
4. 遵守 T+1、整手、涨跌停和停牌规则的模拟撮合；
5. 只读观察期、风控门禁、人工确认后的券商实盘适配器。
