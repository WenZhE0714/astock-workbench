# astock-workbench

一个面向沪深 A 股的终端工作台：用小体积 Go 二进制实时看盘，用独立 Python 适配器调用
TradingAgents-Astock 做多智能体策略研究，并为模拟盘、回测和量化执行预留严格隔离的接口。

## 实时量化辅助选股

Web 的“实时选股”工作区将行情看板、实时因子和历史回测分开：实时层只产生研究信号，不自动下单；历史层继续使用确定性日线回测验证策略。每只候选股会返回 0-100 综合分、各组件 0-20 分、触发观察价、失效参考价、理由、风险和数据时间；实时快照还会把报价的量比、换手、日内高低点和成交额覆盖到扫描输入，抓妖雷达会拒绝超过 10 分钟的同日旧报价。

实时扫描默认读取共用自选，并合并涨幅榜、成交额榜和主力净流入榜候选，最多扫描 50 只股票；每只信号记录“自选/榜单”来源。日 K 与沪深 300 基准在扫描器内存缓存 15 分钟，分钟数据只加载活跃度最高的 6 只。Web 服务启动后由服务端每 30 秒自动扫描，不要求浏览器页面保持打开；浏览器只轮询最新快照，不会再重复发起自动扫描。信号验证改为交易日收盘后调度：15:30 首次执行，若基准日 K 尚未更新到当天则在 16:05 仅重试一次；服务在验证窗口之后启动时会补跑尚未完成的当日任务，盘中不再每 30 分钟重复下载历史数据。四个影子基线账户（均衡、稳健、进取、自适应校准）以及一个独立抓妖实验账户跟随每个新的实时扫描快照推进；抓妖账本只验证雷达阶段，不改写基线账户。同一报价水位会去重，当前日盘中推进只读取本次快照和持仓报价，不会每 30 秒重放全部历史信号。交易时段之外冻结扫描；开盘/收盘检查点变化仍会独立结算，收盘后保留最终快照。页面仍可手动立即触发扫描或信号验证，服务端会用同一运行锁避免重复扫描。信号按交易日写入 `~/.local/share/astock-workbench/realtime-signals/YYYY-MM-DD.jsonl`，自动调度元数据落在 `~/.local/share/astock-workbench/automation/state.json`，`GET /api/strategy/automation` 可查看自动任务状态。

自动任务接口中的 `task_states` 固定按“扫描、验证、影子、研究”顺序展示，每项包含状态、详情、最近尝试/成功时间、下一次计划时间和错误。`waiting` 是等待收盘窗口、日 K 重试或下一交易日，`paused` 是交易时段或数据条件不满足，`error` 才表示本轮执行失败；`POST /api/strategy/automation?action=run` 返回 `202` 仅代表异步任务已接受，页面会继续轮询最终状态。

实时量化不是每秒重新下载全部历史数据，而是缓存低频因子，把实时行情、资金和板块数据增量合并后重新评分。信号状态包括“触发、观察、偏弱、数据不足”，不等价于买入或卖出指令；涨跌停、停牌、流动性、T+1 和个人仓位仍需人工复核。

抓妖雷达是与九因子评分并行的高波动观察模型，不会改变综合分、校准权重、组合资格或四个基线账户的执行逻辑；只有独立的“抓妖实验型”纸面账户会显式消费雷达门控。它根据已完成日 K、当前报价、涨跌停边界、板块广度/资金和市场状态标记“潜伏、启动、加速、高位分歧、退潮、数据不足”；实时快照另外计算开盘跳空是否守住、开盘 15 分钟区间上破、日内价格位置、前高突破失败和量价背离。分钟点会先按交易日和报价时刻过滤，开盘区间未完整形成或报价过期时只保留可审计的降级状态，不把未来点回填到当前信号。只有报价日期、涨跌停边界、前高结构、板块和市场上下文完整且无硬风险时，才进入雷达观察池。缺少边界时仍展示历史结构，但置信度会降级；高位分歧、退潮、极端换手/量比、突破失败、低开失守、熊市和高波动环境不会自动追涨。前向验证会按抓妖阶段单独汇总，避免把情绪模型混入九组件的 IC/权重校准。

Web“实时选股”页顶部提供“实时候选 / 影子账户 / 信号验证”三个工作视图，避免研究诊断只能在长页面底部查看。影子账户采用“历史日线 + 当前盘中事件”的确定性撮合：四个基线账户和抓妖实验账户分别使用独立配置、现金、持仓、订单和 T+1 账本；历史信号在次日开盘生成操作，当前交易日只在 09:30-11:30、13:00-15:00 的已到达实时行情时点处理开仓、加仓、减仓、做T和风险退出，午休与收盘后不伪造交易事件，只做估值/结算。抓妖实验账户仅使用独立雷达门控和分数，并在 09:30 后前 10 分钟进入开盘观察期：这段时间仍持续记录信号和风险，但不新开仓、加仓或做 T 高抛；风险退出与已有 T 回补保持响应，09:40 后才恢复新增仓位。该规则只作用于抓妖账户，结果用于前向比较，不会改变四个基线账户。页面展示账户对比、组合约束、分批持仓、有限换仓、费用、容量、实时事件和决策原因；它不是券商实时委托或分时成交回报。

实时信号的前向验证结果通过 Web“信号验证”视图或以下接口更新和读取：

```text
GET  /api/strategy/realtime?view=outcomes&limit=2000
POST /api/strategy/realtime?view=outcomes&horizons=1,3,5,10
```

评估按信号日之后的交易日计算 1/3/5/10 日窗口，记录开盘入场、窗口末收盘收益、最高有利/不利波动、触发价/失效价命中和相对沪深 300 的超额收益。每只股票每天只保留最后一次扫描作为代表信号，避免 30 秒自动刷新放大样本。抓妖阶段另有独立前向门禁：每阶段至少 20 个成熟样本、5 个不同交易日和 10 个通过雷达门控的可执行样本，未满足时只给出继续采集建议，不调整雷达分数或仓位。原始信号写入 `YYYY-MM-DD.jsonl`，结果修订写入 `outcomes-YYYY-MM-DD.jsonl`；待成熟窗口会在后续更新中升级为成熟结果，已成熟结果不会被无效数据回退覆盖。

影子账户通过以下接口读取或重建：

```text
GET  /api/strategy/shadow?profile=balanced
GET  /api/strategy/shadow?profile=conservative
GET  /api/strategy/shadow?profile=aggressive
POST /api/strategy/shadow?profile=all&selected=balanced
POST /api/strategy/shadow?profile=balanced&rebuild=1
```

切换到“影子账户”或停留期间只读取现有报告，并用 Level-1 最新价更新未平仓持仓的市值、总资产和浮动收益。四个基线账户与一个抓妖实验账户从同一份信号归档读取数据，但分别保存到 `shadow-report.json`、`shadow-report-conservative.json`、`shadow-report-aggressive.json`、`shadow-report-adaptive.json` 和 `shadow-report-monster.json`，切换页面不会共享或改写持仓。账户按“开盘检查点 / 收盘检查点”推进：历史信号在次日开盘撮合；当前交易日的实时信号和持仓风险在每个已到达报价时点处理，同一报价时点去重，午休期间只保留上一水位并更新估值，收盘后只做日线结算。普通 POST 会增量推进当前水位，只有显式带 `rebuild=1` 才允许重算。影子重算默认读取全部信号归档，避免高频扫描把较早的 T+1 信号挤出固定条数。总资产等于可用现金加持仓市值，累计收益包含已实现与未实现盈亏；成交额仅表示买入和卖出流水，不是总资产。盘中行情不会追溯修改已经结算的成交、数量或现金；当前不模拟盘口排队、部分成交和撤单。

仓位管理借鉴 Qlib `TopkDropoutStrategy` 的 `topk / n_drop / hold_thresh / only_tradable` 约束、LEAN 的信号/组合/风险/执行分层，以及 Freqtrade 的仓位调整保护。均衡型组合最多投入 80%，保留 20% 现金缓冲；单日新增资金最多 35%；单股硬上限 20%，实际目标仓位再按综合分、波动风险、市场适配和失效距离动态缩小，并分成最多 3 个批次。单股风险预算默认为初始资金的 1.5%，组合风险预算 6%，单行业按成本最多 30%；风险距离至少按 3% 计算，避免过窄失效位把仓位放大。后续信号比上次仓位信号高至少 4 分时才新增一批，低至少 4 分时于下一交易日开盘卖出最老且满足 T+1 的批次，否则仅记录持有或等待。

`tplus1-v9` 增加横截面有限换仓。均衡型最多持有 8 只、单日最多轮换 2 只；只有新候选比分数最低且可轮出的持仓领先至少 8 分，旧持仓全部批次满足 T+1、至少持有 2 个交易日且开盘可交易时，才先轮出再轮入。稳健型使用 `6 仓 / 1 换 / 领先 10 分 / 最少 3 日`，进取型使用 `10 仓 / 3 换 / 领先 6 分 / 最少 1 日`。替代买入必须先通过现金、行业、组合风险、成交容量和整手预演；预演失败不会先卖旧仓，同一股票当日轮出后也不会立即买回。这是受控的组合质量迁移，不是每次排名变化都追涨杀跌。

风险层只读取已经完成的日 K：若前一交易日收盘跌破归档失效位，或按持仓成本计算的亏损达到 10%，则下一可交易日开盘退出全部满足 T+1 的批次；跌停、停牌时保留待退出状态并顺延，风险退出后同股票冷却 3 个交易日。若信号后的次日开盘已经低于失效位，则直接拒绝追认原买入信号。日 K 模型不会伪造盘中止损、移动止盈或分钟级高抛低吸；旧账户成交不会因策略升级被追溯重写，原有接近满仓的账户会通过后续减仓、风险退出和到期退出逐步恢复现金空间。

面板同时展示覆盖率、正收益率、平均收益、超额收益、IC/Rank IC、分数分层、有效组件归因、组件相关性和信号日前的市场状态稳定性。组件归因只统计分数达到“观察”阈值且数据完整的有效票，并使用组件自己的分数计算 IC/Rank IC，避免不同组件因共同存在而得到相同统计；组件覆盖率与相关性按“股票 + 信号日”去重，不会被 1/3/5/10 日窗口重复放大。相关性使用成对完整样本的 Pearson 与 Rank correlation，至少 20 个成对样本后才判断重叠或反向；状态稳定性只使用成熟且具备沪深300同期收益的结果，每个“组件 × 市场状态 × 窗口”单元至少需要 8 个可用样本和 5 个激活样本，不足时显示 `--`。市场状态只使用信号时点之前的沪深300日K，按高波动、牛市、熊市和震荡分组，避免未来行情泄漏。

当前实时评分包含趋势突破、均线回踩、相对动量、量价确认、波动风险、流动性质量、资金承接、板块轮动和市场适配九个组件；综合分按因子族权重聚合，趋势突破/均线回踩取较优形态，波动与流动性合计占 15%，其中波动与流动性属于风险/质量维度，不应被理解为独立买入信号。扫描完成后会同时记录全池排名和“可交易池排名”：后者只包含状态有效、风险覆盖可用且关键组件覆盖足够的信号，Top-k 组合资格不再被数据不足候选稀释；原始综合分保持不变，市场状态覆盖层单独生成风险调整分和风险乘数，触发/观察状态按风险调整分判定。牛市、震荡、熊市、高波动分别使用 100%、85%、60%、45% 风险预算；基准数据不足时不会把信号纳入新增组合仓位。只有风险调整分达到 55、调整后状态为触发/观察、进入可交易池前 30% 且未触发行集中度保护的信号才标记为组合候选，影子账户对带覆盖字段的新信号使用该资格和风险乘数缩放仓位，旧归档信号按兼容路径处理。滚动研究至少需要 35 个成熟代表信号、5 个不同交易日，并要求九组件覆盖率均不低于 70%；同一交易日的多只股票不能替代时间序列证据，充分样本组件对还会检查 Rank correlation 不低于 0.75 的信息重叠。历史回测现在注册七种日线入场模型：放量突破、趋势收复、均线回踩、动量延续、均值回归反弹、波动收缩突破和自适应多形态；每种模型共享同一 T+1、费用、滑点、整手、止损止盈和无未来数据引擎，优化器与多Agent候选会跨模型比较。盘中实时因子只使用已完成日 K，若排除当日未完成 K 后历史不足，会显示数据不足而不使用部分 K 凑样本。历史回测复用同一状态契约，按状态复合策略与沪深300日收益，并展示状态内收益、最大回撤、入场交易数和超额收益；这些指标用于条件归因，不代表已经形成状态切换策略。样本达到门槛后才生成按时间顺序的 walk-forward 阈值候选和组件权重提案。服务端收盘后每天检查持续优化是否拥有新的非重叠留出窗口，满足时自动运行无 AI 的确定性滚动研究；候选不会自动批准或替换 Champion，策略晋级仍需真实时间观察和人工批准。该流程借鉴 Qlib 的因子分层/IC 分析、LEAN 的 Alpha/风险/组合分层与 Freqtrade 的保护机制思路，但仍受不复权日 K、静态股票池和数据源时效限制。

“滚动验证”页按 1/3/5/10 日验证窗口分别输出组件的两折时间样本外结果。同一交易日不会同时进入训练与验证；每折候选权重只使用此前日期，根据归一化后的训练期平均超额和 Rank IC 生成，再检查后续窗口的超额收益、命中率、Rank IC 与权重漂移。至少需要 35 个组件可用样本、每折 8 个验证样本和 5 个激活样本；跨折候选权重变化超过 20% 时标记为权重漂移。

“组合约束”页按信号日检查综合分不低于 55 的触发/观察候选。单日至少 5 只候选才形成组合日，至少积累 5 个组合日后才进入门禁；行业信息覆盖率要求不低于 70%，单一行业占比不高于 40%，单一活跃组件占比不高于 60%，高相关组件配对比例不高于 30%。这些结果只用于指出候选池的集中风险，不会自动删票、修改综合分或提交订单。

设计参考了开源量化系统的通用分层思想：[Microsoft Qlib](https://github.com/microsoft/qlib) 的因子与横截面排序、[vn.py](https://github.com/vnpy/vnpy) 的事件驱动、[Backtrader](https://github.com/mementum/backtrader) 的数据/策略/撮合解耦、[QuantConnect LEAN](https://github.com/QuantConnect/Lean) 的信号组合与风险管理。项目只借鉴架构原则，不复制其代码，也不要求安装这些项目的运行时。

新闻继续使用原有数据源。

通达信 TCP 是持久连接上的请求/响应协议，不是 WebSocket，也不是服务器主动推送。它能避免
每次刷新都建立 HTTP 请求，但程序仍会按 CLI/Web 的刷新间隔主动查询；公共节点不承诺 SLA，
生产使用应保留当前自动回退和合理的请求间隔。

## 日线策略回测

持续看盘时优先按 `t` 使用统一策略研究页面。以下命令适用于自动化脚本或需要精确传入全部参数的场景。

回测引擎使用固定的不复权日 K，默认运行“放量突破 + MA20/MA60 趋势”策略，也可切换动量延续、均值回归反弹和波动收缩突破。信号在当日
收盘后生成，实际买卖安排在下一可成交交易日开盘，模拟 A 股 T+1、100 股整手、佣金、最低佣金、
卖出印花税、过户费和双向滑点。止损、止盈、跌破快线和最大持有期均为可配置的确定性规则。
长历史优先复用 14 天内、且覆盖请求区间的本地日 K 缓存；缓存不足时使用腾讯明确的 `none` 不复权序列分段请求，失败后回退东方财富及其兼容代理。普通日 K 与回测共用这条多源回退链路，实际来源会写入结果。

运行回测：

```bash
astock backtest run \
  --start 2022-01-01 \
  --end 2025-12-31 \
  --cash 1000000 \
  --max-position 0.20 \
  --slippage-bps 5 \
  600519 000001 300750
```

查看历史、汇总和交易买卖点：

```bash
astock backtest list
astock backtest show <run-id>
astock backtest trades <run-id>
astock backtest trade <run-id> T0001
```

单笔交易会分别列出信号日期和实际成交日期、信号时的均线/前高/量比、买卖理由、原始开盘价、
滑点后成交价、股数、费用、持有天数、净收益、最大浮盈、最大浮亏和退出原因。每次结果保存在：

```text
~/.local/share/astock-workbench/backtests/<run-id>/
├── summary.json       # 完整回测结果、指标、交易和未平仓
├── strategy.json      # 策略参数与交易成本快照
├── report.md          # 可读报告和交易摘要
├── trades.jsonl       # 逐笔交易审计记录
└── equity.csv         # 每日现金、持仓市值、权益和回撤
```

当前限制会写入每次报告：不复权序列跨除权除息可能失真；静态输入股票池不等于历史点时成份股池；
日 K 只能识别一字板，不能重建盘中涨跌停排队和真实成交概率；交易费率按本次参数固定，不会伪装成
按历史政策日期自动切换。回测归档将作为后续训练/验证/样本外
划分和 AI 参数建议的输入，但 AI 不会直接修改成交记录或绕过撮合规则。默认期末强平按最后可成交日
收盘价做估值收尾并计入卖出成本，报告会明确它不是次日开盘的真实成交。

### 训练、验证与样本外优化

策略优化使用受控的确定性参数候选，默认最多 30 个。候选只根据训练集和验证集评分，并经过验证
交易数、最大回撤、最低收益、训练/验证年化差距和有限数值门禁。参数锁定后才执行一次样本外回测；
样本外结果不会用于重新挑选参数。每个区间从相同初始资金独立开始，不跨区间携带持仓，预热日 K
只取该区间开始日之前的数据。候选复用进程内历史区间缓存，不会按候选数重复请求相同行情。

```bash
astock backtest optimize \
  --train-start 2018-01-01 --train-end 2021-12-31 \
  --validate-start 2022-01-01 --validate-end 2023-12-31 \
  --oos-start 2024-01-01 --oos-end 2025-12-31 \
  --max-candidates 30 \
  600519 000001 300750

astock backtest optimize-list
astock backtest optimize-show <experiment-id>
```

默认在确定性实验结束后调用临时、只读、非交互的 Codex 复盘训练/验证泛化差距、参数敏感性和
失效场景；用 `--no-ai` 可关闭。AI 只能输出复盘文本，不能生成成交、改写指标、绕过验证门禁或
按样本外结果重选参数。AI 失败也会保留完整实验。实验单独保存在：

```text
~/.local/share/astock-workbench/backtests/optimizations/<experiment-id>/
├── summary.json
├── candidates.jsonl
├── selected-strategy.json
├── report.md
├── ai-review.md                 # AI 成功时存在
├── train/                       # 入选候选的完整回测归档
├── validation/
└── out-of-sample/
```

参数搜索和样本外盈利都不等于“稳定收益”。当前仍使用静态输入股票池、固定历史费率和不复权日 K；
基础回测已经提供点时市场状态归因，正式研究仍应增加历史点时股票池、公司行动处理，并把状态分层
推进到滚动样本外检验和流动性压力测试。

### 多Agent持续优化

持续模式使用 Go 主协调器并发启动三个只读子 Agent，分别从稳健风控、趋势捕获和参数平台稳定性
提出结构化候选。子 Agent 只能修改受控技术参数，不能看到最终留出结果，不能修改股票池、仓位上限、
费用、滑点、复权、评分或晋级门槛；任一 Agent 超时或格式错误时，确定性基线候选仍会继续研究。

```bash
astock backtest continuous 600519 000001 300750
astock backtest continuous-list
astock backtest continuous-show <experiment-id>
```

当前策略族支持七种入场模式。候选默认经过4折滚动训练/验证；
参数锁定后才运行最近3个月的最终留出集，并用双倍交易成本与最佳单笔利润集中度做压力测试。只有滚动
正收益窗口、交易数、最终留出收益/夏普/回撤和压力测试同时通过，才标为“模拟观察候选”；否则保留为
“研究候选”。模拟观察候选也不会自动替换看盘信号或下单。Web“量化研究”顶部现在提供独立的候选
生命周期：历史门禁通过后先等待人工批准进入真实时间观察，候选参数从下一个交易日起冻结并进入信号验证；观察
至少 60 个交易日、完成至少 10 笔交易、绝对收益和相对沪深300超额均为正、最大回撤不超过 10%、
股票行情最低覆盖率不低于 90% 后，才进入第二次人工批准。批准时必须填写依据，拒绝和撤销也必须写明
原因并写入 `lifecycle.json` 审计记录。最终批准仅允许该参数成为同股票池下一轮持续优化的研究基线，
不会修改实时九因子评分、五套影子账户或提交订单。

每轮还会生成候选集和完整配置的 SHA-256 指纹，执行无未来数据、滚动窗口、复权口径和行情来源完整性
硬检查，并记录点时股票池和基准的已知限制。多个 Agent 独立提出相同参数会形成共识证据；入选参数
附近没有同样通过门禁的参数邻域时，即使单点评分最高也不会晋级。`continuous-show` 和 `t` 页面会展示
质量评级、指纹、共识、参数邻域、历史反思和全部未晋级原因。

同一股票池的最终留出区间不能重叠，避免在已经查看过的测试集上继续调参。默认至少积累一个新的完整
3个月留出窗口后，才允许启动下一轮；系统只继承最近一条已经通过真实时间观察且由人工批准的候选作为
Champion 基线。较新的研究失败或未批准挑战者不会覆盖已批准基线，所有新候选仍需重新执行全部滚动、
留出与压力测试。

[docs/STRATEGY_RESEARCH.md](docs/STRATEGY_RESEARCH.md)。

主力资金、板块热度和龙虎榜会作为独立短线侧证展示，但不参与基础量价信号打分。

回退到基准日 K 和周末规则，并在页面标记“交易日历未覆盖，按工作日降级”，不会伪造完整节假日信息。
`--moyu` 使用无色紧凑表格，同样显示个股资金流，并在列表顶部显示上证、深证、创业板的指数资金；
`↑` 表示净流入，`↓` 表示净流出；普通列表和详情的个股/关联板块资金流最多每 60 秒更新一次，

沪深京 A 股合计；创业板是深市子集，不会重复累加。当前值使用腾讯的上证指数、深证综指和北证 50
成交额字段，上一交易日使用新浪对应指数的 5 分钟成交额逐日精确汇总，不使用成交量估算，也不需要
Token。该口径实测与常见行情软件的“沪深京”总额和缩放量差值一致。

历史数据暂不可用时只显示当前总额，不显示“较昨”；周末、节假日和开盘前若行情日期尚未推进到

指定兼容代理，并使用 `{symbol}` 作为指数代码占位符。

板块排行和龙虎榜数据使用东方财富公开接口。可通过 `ASTOCK_BOARD_RANK_API_URL`、
`ASTOCK_DRAGON_TIGER_API_URL` 指定兼容的代理地址；板块排行按行业/概念缓存 5 分钟，龙虎榜按股票缓存 30 分钟。
个股涨跌幅榜和涨速榜同样使用东方财富沪深 A 股列表接口，行业板块取其 `f100` 分类；可通过
`ASTOCK_MARKET_RANK_API_URL` 指定兼容代理，也可使用 `{metric}`、`{order}`、`{limit}` 占位符。
资金雷达的全行业资金快照使用东方财富行业板块列表接口，可通过 `ASTOCK_INDUSTRY_FLOW_API_URL`
指定兼容代理地址。
板块资金看板使用同一行业板块列表口径按主力净额双向排序，再用板块成份股列表按成交额取前三；
可通过 `ASTOCK_INDUSTRY_SCAN_API_URL` 和 `ASTOCK_INDUSTRY_LEADER_API_URL` 分别指定兼容代理地址。

同花顺 Quant API 为可选行情源，不改变默认的通达信/HTTP 路径。启用前请在同花顺
Super Command 中确认账号已开通实时行情、高频序列和日期序列权限。应用支持本地配置文件：

```text
~/.config/astock-workbench/ths-quantapi.json
```

JSON 文件同时保存连接参数和 Token，建议权限设为 `0600`：

```json
{
  "enabled": true,
  "access_token": "在此填写 access_token",
  "refresh_token": "在此填写 refresh_token",
  "base_url": "https://quantapi.51ifind.com/api/v1",
  "min_request_gap_ms": 100,
  "quote_indicators": "latest,changeRatio,open,high,low,preClose,volume,amount,turnoverRatio,limitUp,limitDown",
  "history_indicators": "open,close,high,low,volume,amount,turnoverRatio",
  "minute_indicators": "latest,avgPrice,volume,amount"
}
```

当 `enabled` 为 `true` 且 `access_token` 已填写时，CLI 和 Web 在未显式指定行情源的情况下会默认使用
同花顺；仍可用 `--source http` 或 `--source tdx` 临时覆盖。

也可以只使用环境变量；环境变量优先于本地文件：

```bash
export ASTOCK_THS_ACCESS_TOKEN='你的 access_token'
export ASTOCK_THS_REFRESH_TOKEN='你的 refresh_token'
export ASTOCK_MARKET_SOURCE=ths
./dist/astock --once 贵州茅台
./dist/astock web --listen 127.0.0.1:8788 --source ths
```

Quant API 请求使用 `access_token` Header。`refresh_token` 当前不会被程序自动交换，
因为公开数据网关没有稳定的 CLI 刷新端点；Access Token 失效时应在同花顺控制台重新生成并
更新本地 JSON。可通过 `ASTOCK_THS_BASE_URL` 覆盖网关地址，通过
`ASTOCK_THS_MIN_REQUEST_GAP_MS` 调高本地请求间隔；指标名称可分别用
`ASTOCK_THS_QUOTE_INDICATORS`、`ASTOCK_THS_HISTORY_INDICATORS` 和
`ASTOCK_THS_MINUTE_INDICATORS` 覆盖。若账号权限不足或返回结构无法识别，系统会自动回退
到现有 HTTP 行情源，并在错误信息中保留原因；不会把 Token 写入日志、报告或浏览器。

Web 的“情绪驾驶舱”通过 `/api/sentiment` 提供指数信号、成交额信号、行业涨跌广度、上涨行业占比、
情绪分数和24小时采样走势，并接入东方财富涨跌停池，提供涨停、跌停、炸板率、最高连板和连板梯队。
涨跌停接口不可用时会明确标记为未覆盖，不会用0填充；
情绪分数只作为观察和研究输入，不会直接改变九因子或影子账户基线。
情绪采样会持久化到 `~/.local/share/astock-workbench/sentiment/history.json`，重启后恢复最近24小时、最多360个点。
默认优先请求东方财富数据中心，失败时回退到涨停池接口；可通过
`ASTOCK_LIMIT_STATS_API_URL`、`ASTOCK_LIMIT_STATS_POOL_API_URL` 以及对应的
`ASTOCK_LIMIT_*_REPORT` 变量接入兼容代理。

Web 另提供“板块行情”Tab，通过 `/api/boards` 展示行业涨幅、主力净额、上涨/下跌家数和强弱排序；
选中板块后会在页面内积累盘中采样并绘制分时曲线，也可以一键打开板块行情详情。

驾驶舱还会按30秒缓存读取同花顺公开信号端点：北向资金盘中累计净流入、当日热点股数量和题材归因。
这些信号作为情绪辅助层和选股证据展示，不会单独触发交易；北向历史序列不作为长期回测依据，热点题材标签也不替代公告、财报等正式证据。
如需使用兼容代理，可分别设置 `ASTOCK_THS_NORTHBOUND_URL` 和 `ASTOCK_THS_HOT_STOCKS_URL`；热点地址支持 `%s` 占位符传入交易日。

自选股：

```bash
./dist/astock add 贵州茅台 宁德时代
./dist/astock remove 宁德时代
./dist/astock list
./dist/astock                 # 读取已保存自选并持续刷新
```

持续看板支持有序分组。按 `f` 打开分组列表，方向键选择、`Enter` 切换；列表内按 `n` 新建分组、
按 `d` 删除分组。看某个具体分组时，`a` 添加到该组，`d` 只从该组移出；在“全部”视图按 `d`
才会从所有分组删除。删除分组不会丢失独有股票，它们会自动移到“默认”。

按 `e` 进入排序模式：先用方向键选择股票，第一次 `Enter` 锁定，继续用方向键移动，第二次
`Enter` 保存；任一阶段按 `Esc` 都会恢复进入排序前的顺序。“全部”是多个分组的汇总视图，
需要先按 `f` 进入具体分组再排序；只有“默认”一个分组时，启动后可直接按 `e`。

分组仍保存在兼容的 `~/.config/astock/watchlist` 文本文件中，使用 `[分组名]` 标题；旧版单列表
会自动作为“默认”分组读取。`astock list` 会按分组罗列自选。

通过 `i` 或 `h` 成功打开的最近 100 只股票保存在
`~/.local/share/astock-workbench/view-history.tsv`，普通列表中按 `Enter` 查看不会写入这份历史。

兼容原来的简写：`astock 600519`、`astock --moyu 600519`、`astock --add 600519`。

## 接入 TradingAgents-Astock

`watch` 完全不需要 Python。只有 `analyze` 需要：

1. 一个可工作的 `tradingagents-astock` checkout；
2. 该项目的 Python 3.10+ 虚拟环境；
3. 对应模型供应商的 API 凭证。

本机已有项目时，先自检：

```bash
./dist/astock doctor --repo /Users/wenzhe/tradingagents-astock
```

运行一次分析：

```bash
./dist/astock analyze --repo /Users/wenzhe/tradingagents-astock 600519
```

也可以固定环境，之后不再传路径：

```bash
export ASTOCK_TRADINGAGENTS_HOME=/Users/wenzhe/tradingagents-astock
export ASTOCK_TRADINGAGENTS_PYTHON=/Users/wenzhe/tradingagents-astock/.venv/bin/python
./dist/astock analyze 贵州茅台
```

覆盖模型配置的例子：

```bash
./dist/astock analyze \
  --provider deepseek \
  --deep-model deepseek-chat \
  --quick-model deepseek-chat \
  600519
```

未显式传入时，provider、模型和 backend URL 均沿用 TradingAgents-Astock 的
`DEFAULT_CONFIG` 与环境变量。模型密钥不会复制进本项目，桥接进程只继承当前环境并读取
TradingAgents 项目自己的 `.env`。

一次完整分析通常会产生 30–50 次模型调用，可能耗时数分钟并产生 API 费用。`doctor`
只验证本地环境，不发起正式分析。

## 分析结果

结果默认保存到：

```text
~/.local/share/astock-workbench/reports/<股票代码>/<分析ID>/
├── analysis.json
└── report.md
```

查看历史：

```bash
./dist/astock reports list
./dist/astock reports show 600519
```

稳定 JSON 契约包含：标的、分析日期、五档组合评级、provider/model、数据供应商、全部
分析师报告、研究/风险辩论结论和最终组合决策。后续策略、回测和模拟盘只消费该契约，
不直接导入 LangGraph。

## 数据和风险边界

- 实时表格是公开 Level-1 快照，不等同于交易所直连行情，也不保证逐笔或毫秒级实时性。
- 个股和指数资金流来自东方财富公开口径，是市场行为参考；主接口不可用时会回退到公开延迟节点。
- 指数资金分别对应三大指数的主力净额，指数成分股存在重叠，不能把三项相加当作全市场总额。
- 技术判断使用未复权历史日 K 和量能；实时快照只用于展示与分析时点提示。日线信号不等同于盘中高频点位。
- 财务、公告、减持、合同等正式结论应回到交易所或巨潮资讯原文核验。
- 报告和详情页输出是情景研究信号，不是确定性买卖建议；应明确触发条件、仓位和失效条件。
- 研究、回测、模拟撮合和未来实盘 Broker 是不同进程/接口，实盘层必须再经过确定性风控与人工确认。
- 回测实现时必须固定复权口径，并处理未来函数、幸存者偏差、点时股票池、手续费和滑点。

## 分发

构建 macOS Intel、Apple Silicon 和通用二进制：

```bash
make dist-macos
```

实时看盘只需把匹配朋友机器架构的单个二进制发给他：

```text
dist/astock-darwin-arm64       Apple Silicon
dist/astock-darwin-amd64       Intel Mac
dist/astock-darwin-universal   两种 Mac 通用，但体积约等于两者之和
```

朋友首次运行若被 macOS Gatekeeper 拦截，可自行执行：

```bash
xattr -d com.apple.quarantine ./astock-darwin-arm64
chmod +x ./astock-darwin-arm64
./astock-darwin-arm64 watch 600519
```

如果朋友还要使用 `analyze`，仅发送 Go 二进制不够；还需给他安装
TradingAgents-Astock、Python 环境和自己的模型 API Key。不要分享你的 `.env` 或 API Key。
