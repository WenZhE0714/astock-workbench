# 后台价位提醒

入口：「监控中心 → 价位提醒」，或`/?view=monitor&monitor=prices`。冻结交易复盘中的铃铛也使用同一套后台规则。创建草案不会落盘，「确认并启用后台提醒」才发送创建请求；规则不下单，不修改策略、前瞻日档或影子账户。

## 状态与执行

Web服务运行时，每30秒按现有行情客户端获取报价。浏览器只展示状态，不负责触发。创建、启用会唤醒检查；一个数据目录由一个持有文件锁的检查进程负责。退出时释放锁，下一进程可接管。

- 只支持A股股票，价格为正的有限数值，有效期在创建当日至一年内。
- 只在上海时间周一至周五9:30至11:30、13:00至15:00检查触发条件；还要求股票代码匹配、同日报价、非未来时间且新鲜度不超过90秒。没有当日真实新报价时不会按工作日补造行情或触发。
- 报价必须来自本次启用之后，且时间晚于上一份已处理报价，避免旧报价重用。
- 达到或高于/低于价位时生成一个终态事件，关闭该规则。已触发、到期和删除的规则不再触发；需要再次监控时复制为新规则并确认。
- 暂停、恢复和删除使用配置修订号，旧页面不能覆盖更新的控制状态；行情请求在锁外进行，保存时重新读取控制状态。

## 存储和通知

数据文件位于应用数据目录的`notifications/price-alerts.json`，与前瞻数据和交易账本分开。文件锁串行化多进程更新，原子写入。规则内容、创建时间和已触发事件不可被后续检查改写；删除使用保留事件的墓碑记录。文件损坏时停止并显示错误，不自动清空。

触发事件先持久化，再作为稳定ID的待投递事件提交现有通知Dispatcher。队列满或进程在提交前退出时，可从文件恢复；Dispatcher复用已提交去重、最多3次尝试、静音和5分钟通知时效。通知晚于时效不会补发过期横幅，但规则触发记录仍可查询。「已提交系统」不代表用户一定看到了横幅。外部系统发送成功、进程恰在提交结果落盘前退出的极短窗口无法承诺严格一次投递。

启用Mac通知需要运行`astock web --mac-notifications`，常驻服务可沿用现有同名选项。不要对同一数据目录同时启动多个开启Mac通知的实例。系统通知沿用既有的点击定位、已读/已处理和股票当天静音能力。未开启Mac通知仍会记录触发事件，不伪造投递成功。

## API与来源

`GET /api/price-alerts`返回规则、检查状态和通知记录。`POST`支持`create`、`enable`、`delete`，复用现有同源JSON校验，拒绝跨站请求、未知字段和额外正文。创建要求`confirmed=true`及幂等请求标识；相同标识不能创建不同规则。最多保留100条尚未结束的规则。

使用`ASTOCK_WEB_API`运行Vite预览时，代理保留原Host，使浏览器Origin与后端校验一致，并关闭开发服务器的跨域读取；不通过放宽后端同源检查来兼容预览。

来自复盘的规则保留来源ID、日期和日档指纹。创建时从服务已配置的归档核对股票池、哈希链、日档指纹及时间；客户端不能传入文件路径。手动输入股票的规则不伪装成已验证的冻结来源。

## 迁移与回放

旧浏览器键`astock.replay-price-alerts.v1`不自动变成后台规则。页面显示原先启用且未触发的旧规则，逐条确认后迁移；服务端保存成功后才清理对应旧记录。原先停用或已触发的旧数据继续保留在原浏览器键中。迁移请求使用稳定标识，网络重试不会重复建规则。

回放页面隐藏实时提醒状态，但已确认的后台规则继续监控当前报价，独立于历史回放。Mac需保持登录、唤醒且代理/行情源可用；关闭Web服务、睡眠或关机期间不能检查。

## 验证

- 领域测试：上下界相等、单次事件、旧/未来/错股票报价、启用前报价、午休/周末、暂停、到期和删除。
- 存储测试：并发触发、重启、工作锁释放、规则/事件改写拒绝及损坏检测。
- API及工作循环测试：明确确认、同源控制、创建幂等、修订冲突、无浏览器触发、待投递事件恢复和停止生命周期。
- 浏览器隔离测试：关闭全部页面后改变测试报价，后台仍触发；重开后保留记录且不重复提交；覆盖迁移确认、删除、复盘来源与移动布局。通知使用记录型发送器，不调用真实macOS通知。

`go test ./internal/strategy ./internal/storage ./internal/web ./internal/notify`运行相关测试。浏览器夹具由`ASTOCK_PRICE_ALERT_BROWSER_PORT`显式开启，仅存在于测试二进制中，不能作为正式服务使用。
