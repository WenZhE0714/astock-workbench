# 固定候选的仓位对照

`backtest position-study` 从已归档的持续研究中选择一个候选，只改变单股最大仓位。默认比较20%、15%、10%；入场模式、均线、止损止盈、持有期、股票池、资金和基础费用全部继承源实验。

```sh
go run ./cmd/astock backtest position-study \
  --output /path/to/new-study \
  AUTO-20261015T160220 P008
```

`--caps 0.20,0.15,0.10` 可指定2至8个唯一比例，必须包含原候选的仓位值。输出目录必须不存在，避免覆盖已有证据。数据只读取所选证券和沪深300的本地缓存，不请求行情接口，也不触发影子账户同步或候选晋级。

## 输入与计算

命令先复制执行日K与扫描日K缓存到研究目录，并把每个文件的SHA-256、源实验完整配置和仓位列表写入 `plan.json`。优先使用执行历史缓存，覆盖不足时使用扫描历史缓存的完整请求区间，不在同一请求内拼接两个来源。所有仓位共用同一冻结输入和现有日线回测引擎。

依次执行原研究的验证窗口，正常成本与双倍成本各跑一次；双倍成本同时加倍佣金、最低佣金、印花税、过户费和滑点。固定参数不重新训练，也不重新搜索入场模式。

常规检查沿用原研究的最低交易数、正收益窗口比例及最大回撤阈值，并要求基准可用和逐证券数据覆盖至少80%。双倍成本使用相同检查作为额外稳健性诊断。原基线的每折收益、回撤和交易数量会与源报告逐项比较，差异单独记录。

源研究原有的近期区间已被观察，本命令将其标为 `seen_period_diagnostic`，不称为新的最终留出。该区间不改变验证窗口的检查结果。无论回测是否通过，`promotion_allowed` 始终为false；仍需要新数据和后续前向检验。

## 产物

- `plan.json`：冻结配置、源实验和输入文件指纹。
- `cache/`：本次实际使用的本地输入副本。
- `result.json`：各窗口的交易、净值、数据覆盖及指标；`completed`区分完整运行与中断结果。
- `report.md`：完整运行后的比较表。
- `error.json`：失败时保存的错误，已经完成的结果仍保存在 `result.json`。

本工具仍沿用不复权价格、固定费率及日线撮合假设。静态股票池可能存在幸存者偏差；回撤降低不等于信号产生了正期望。离线缓存缺失、过期或不能复现旧基线时，必须说明限制。

窗口收益包含期末未平仓持仓的盯市盈亏。即使启用期末清仓，最后交易日新买入的持仓仍受T+1限制，不能当日卖出；应同时查看结果中的 `open_positions`，不要把窗口收益全部解释为已实现收益。
