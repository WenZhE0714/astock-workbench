# 前瞻采集与成交自动验收

`cmd/forward-acceptance`是独立的只读检查程序。它复用已有存储校验，对配置、源研究、日档哈希链和采集程序指纹进行核验，再检查首日日档及每次后续日档转换的四组账户。它不执行采集程序，不访问行情网络，不改变冻结策略，不写入交易，也不把历史演练纳入观察样本。

## 检查内容

- 首日日档无前序指纹，四组账户完整，股票池及基准均有首日日K和足够的预热数据。
- 采集时间在当日15:30至19:00，日期不早于冻结起点且不晚于验收时间。
- 四组请求与冻结配置一致，双倍成本的费用和滑点正确。
- 首日无成交、无持仓、无费用，现金和净值等于各自初始资金，无回撤。
- 待执行订单只允许来自首日的买入信号，不允许重复股票。
- 候选信号精确等于原信号中量比至少1.5的部分，其余信号须有对应过滤记录；双倍成本组首日信号一致。
- 首日不得满足样本数量或允许晋级。没有信号也可以通过初始状态验收。

## 成交与资金核对

每次运行从首日重新核对至本次读取的归档末端。对每对相邻日档，使用当日封存的不复权日K、原配置及原采集时刻，调用既有前瞻引擎复算。成交、持仓、待执行信号和量比过滤记录须与复算一致；所有历史净值点以及累计费用、最终净值、回撤和换手金额也须一致。金额比较容差为`1e-6`元，拒绝非有限数值。对有缺K、历史OHLCV修订、漏采或时间边界错误的输入停止验收。

同时独立核对开盘账务，避免只依赖同一引擎的输出对比：

- 每次新增买入或卖出须对应前一份已封存日档的待执行信号，信号日期早于成交日期；顺延信号可以来自更早日期。
- 卖出必须对应原有持仓，股数及入场记录一致，买入日早于卖出日，禁止同日买卖和期末强制平仓。
- 使用当日日K开盘价加减冻结滑点，逐项重算成交金额、佣金、最低佣金、卖出印花税及过户费；股数为正的100股整数倍。
- 按引擎固定的股票顺序重建开盘现金及持仓。每笔买入金额含费用不得超过可用现金及当时账户开盘净值的单股仓位上限；既有持仓用当日开盘价估值，不使用当日收盘价决定买入预算。
- 一字板上的既有信号不得成交，且须原样保留为待执行信号。缺少股票日K时暂停，而不生成停牌填补数据。
- 逐项核对收盘持仓数量、价格、市值、未实现盈亏、现金、账户净值和累计费用。

只有整日四组账户全部通过，才累计这次日档转换的买入、卖出和一字板顺延次数。报告分别记录各组首次买入和首次卖出日期；尚未成交的组不会被计入首次成交通过数量。

## 状态与产物

输出目录必须位于前瞻归档之外；每次原子更新`status.json`和`report.md`。配置指纹通过命令行显式固定，配置变化不会被自动接纳为同一个验收对象。

| 状态 | 含义 |
|---|---|
| waiting | 完整性检查通过，尚无首日日档 |
| attention | 起始日期的采集窗口已过，仍无首日日档，需要核对交易日安排和采集日志 |
| error | 配置、源研究、程序或日档校验失败，或采集任务报告错误 |
| passed | 最早日档符合首日验收条件 |

顶层`status`保留归档与首日验收含义；后续成交校验失败时同样变为`error`。`attention`不直接认定漏采交易日，因为本程序没有独立交易所日历；假日也需要结合采集状态核对。程序只更新本地报告及日志，不发送通知。

新增的`execution`字段明确区分首次成交的观察进度：

| execution.status | 含义 |
|---|---|
| waiting-first-day | 尚无首日日档 |
| waiting-next-day | 首日通过，等待后续日档 |
| waiting-fill | 已核对后续日档，但四组均无买入 |
| partial | 部分账户发生并通过首次买入核验，其余等待 |
| passed | 四组各有至少一次已核验买入，继续核对后续成交 |
| paused | 采集任务报告错误，暂停成交验收 |
| error | 某次日档转换或成交账务核验失败 |

成交`passed`不要求已经发生卖出，各组卖出覆盖须查看`first_sell`和`sells`；没有卖出就没有实际卖出或T+1的观察证据。所有状态均不等于策略晋级或真实订单成交保证。

即使已有首日日档，后续采集错误也会报告，不再只检查首日前的错误。读取过程中若归档末端变化，报告要求重试，下一次调度重新读取。复算有2分钟时限，超时不会宣称完成。验收过程不持有采集写锁。

## 运行

```sh
go build -trimpath -o /path/to/astock-forward-acceptance ./cmd/forward-acceptance
/path/to/astock-forward-acceptance \
  --archive /path/to/frozen-forward \
  --binary /path/to/frozen-collector \
  --output /path/to/separate-acceptance-output \
  --fingerprint EXPECTED_PLAN_FINGERPRINT
```

新输出目录的父目录需要已存在。使用配置中保存的程序SHA-256核验采集程序，验收程序本身不替换该程序。

## 本机任务

- LaunchAgent：`com.github.wenzhe.astock-workbench.volume-forward-acceptance`，登录时运行并每300秒检查。
- 程序：`~/.local/share/astock-volume-forward-service/bin/astock-forward-acceptance-v2`；原v1保留。
- 输入：`~/astock-volume-forward-2026-10-19-v2`。
- 输出：`~/astock-volume-forward-acceptance-2026-10-19`。
- 日志：`~/Library/Logs/astock-workbench/volume-forward-acceptance.out.log`和同名`.err.log`。
- 观察起点：2026-10-20；10月19日的正常状态是`waiting`、0个观察日。

该任务与采集任务分别调度，日档生成后通常在下一次检查时反映验收结果。两者均依赖Mac登录且处于唤醒状态；本任务不更改系统休眠设置。

## 验证

`go test ./cmd/forward-acceptance`覆盖首日验收、四组开平仓、部分账户尚无成交、全组无成交、一字板顺延及信号丢失、T+1违规、整手数量、超仓位、费用错误、现金不平、缺K、漏采和历史修订。重新计算哈希后的错误账务仍会被拒绝。`go vet ./cmd/forward-acceptance`通过。

设置`ASTOCK_ACCEPTANCE_REHEARSAL_ARCHIVE`后，额外只读加载既有演练档案并验证全部相邻日档。可用`ASTOCK_ACCEPTANCE_REHEARSAL_REPORT`指定一个尚不存在的JSON文件保存历史核验摘要。

2026-10-19已核对既有演练的55份日档、54次转换（2026-07-16至10月8日），四组买入次数分别为8、2、8、2，卖出次数同样为8、2、8、2。基线两组首次买入7月23日、首次卖出7月24日；量比候选两组首次买入9月9日、首次卖出9月14日。该历史段没有一字板顺延，顺延和T+1异常由可控样本验证。

历史核验结果位于`~/astock-volume-forward-acceptance-2026-10-19/execution-rehearsal.json`，明确标记`real_time_evidence=false`。它不替换自动任务的`status.json`，不计入真实观察日，也没有补齐旧演练因缺K而停止的后续日期。
