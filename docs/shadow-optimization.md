# 影子账本校验与策略对照

本轮采用 `tplus1-v12`。原有五个账户保留各自资金和策略参数；新的优化假设使用独立账户验证，不将历史样本重新撮合成优化收益。

## 账本校验和校正

`astock shadow audit` 校验成交数量、订单引用、平仓数量、金额和盈亏恒等式、现金与费用、空仓未实现盈亏以及持有天数。Web 影子账户页同步显示所选账户的校验结果。

```bash
./dist/astock shadow audit
./dist/astock shadow repair --calendar "$HOME/.cache/astock/daily-history-scan/sh000300.json"
./dist/astock shadow repair --calendar "$HOME/.cache/astock/daily-history-scan/sh000300.json" --apply
```

默认只预检，`--apply` 才修改当前账本。`--profile balanced|conservative|aggressive|adaptive|monster` 可限定账户。日历参数是包含 `bars` 字段的沪深300未复权日K缓存；修复持有天数时必须覆盖真实买入日和卖出日，不按工作日猜测。

自动校正仅支持空仓账户中的可证实异常：

- 移除零数量、零金额的已成交卖单及其零数量平仓记录，退回该错误卖单计入的费用。
- 按交易日期和日历修正不可能成立的持有天数。
- 重新核对现金、已实现与未实现盈亏；仍有其他矛盾时拒绝应用。

每次校正先保存 `<账本文件>.repairs/<原始文件SHA-256>/before.json`、`after.json` 和 `record.json`，然后原子替换活动账本。记录包含前后指纹、校正项目和应用状态。重复执行没有新异常时不再更改账本。中断恢复可核对当前账本与记录中的前后指纹；原始证据不删除，原始决策日志不重写。

修复后的账本增加 `ledger_revision`，同时升级引擎版本。存储拒绝更低修订或更旧引擎写回，防止旧进程恢复异常数据。运行中的旧实例应更新为同一程序版本。

生成新成交时，不再恢复数量为零的持仓批次。持有天数按同一行情序列中的日期计算，避免把不同数据窗口的数组下标相减。

## 独立对照

```bash
./dist/astock shadow trials
./dist/astock shadow trials --apply
```

默认输出拟创建的配置；`--apply` 固定实际创建时间，写入 `paper/trials/config.json`。已存在时读取原配置，不覆盖或重新设定起点。创建后重启 Web 服务，使其加载对照。交易范围沿用实时扫描候选池，同一调度周期的所有账户共用快照。

每个新账户初始资金为100万元，起点完全一致；未到该时点的信号不能用于新账户开仓。配置、引擎版本和指纹固定，修改配置需要另建一组实验。原五账户的累计收益不充当新实验的同起点对照。

| 新账户 | 同起点基线 | 唯一策略差异 |
|---|---|---|
| 均衡对照 | 自身 | 原均衡规则 |
| 均衡不加仓 | 均衡对照 | 禁止普通信号加仓 |
| 均衡延伸上限 | 均衡对照 | 实际入场价高于信号参考价不得超过5% |
| 抓妖对照 | 自身 | 原抓妖规则 |
| 抓妖不加仓 | 抓妖对照 | 禁止普通信号加仓 |
| 抓妖盘中入场 | 抓妖对照 | 禁止历史信号次日开盘入场，只允许盘中事件入场 |

不加仓规则不阻止已有做T卖出批次的回补。延伸上限同时用于日线开盘和盘中实际买入价，缺少参考价时不入场。仅盘中入场不关闭风险退出、T+1、到期退出或已有持仓的日线减仓。

Web“影子账户”可切换“原账户 / 优化对照”。对照页显示固定起点、各账户资金和成交，以及相对本组基线的收益率差；没有平仓样本时显示待积累状态。账本位于 `paper/trials/accounts/`，不与原账户共用现金或持仓。

## 评估边界

5%延伸上限是待检验假设，不是已证明最优的参数。本轮没有降低熊市门槛，也没有取消抓妖的熊市禁入。近期无合格信号时，对照账户同样可能保持空仓。

上线验收只证明规则执行、账本修复和配置隔离正确。策略是否改善须继续观察未来成交，比较同组净收益、资金使用、回撤、尾部亏损和交易成本，样本按日期与证券去重/聚类。不能简单扣除历史加仓亏损，就声称不加仓策略获得相同收益提升。
